# A/B-тест промпта LLM-ассистента

Учебный проект (Zerocoder, модуль 6, урок PEd04 «A/B-тесты, гипотезы, оценка качества решений»).

Показывает, как проверять изменения промпта не «на глаз», а воспроизводимым экспериментом: гипотеза по SMART → заранее зафиксированные метрики и MDE → датасет с «кривыми» запросами → прогон двух версий промпта на одной модели → слепая ручная оценка → решение по данным.

## Что тестировали

Бот объясняет новичкам термины из ИИ и автоматизации.

- **Промпт A (контроль):** «объясняй понятно и по делу».
- **Промпт B (эксперимент):** то же + обязательная структура ответа (Коротко → Аналогия → Пример → Не путать с).

**Гипотеза:** структура повысит полноту объяснения (Completeness, 1–5) минимум на 0,5 балла без роста галлюцинаций.

## Результат

| Метрика | A | B |
|---|---|---|
| Completeness (Primary) | 4,10 | 3,87 (−0,23, p = 0,48) |
| Галлюцинации (Guard) | 7% | 13% ❌ |
| Латентность, медиана | 3,13 с | 2,71 с |

Гипотеза не подтвердилась, **B отклонён**. Жёсткий шаблон заставляет модель «объяснять» несуществующие термины: на ловушках B выдумал ответ 3 раза из 3, A — 1 раз из 3. Подробный разбор — в [homework_answer.md](homework_answer.md).

## Структура

| Файл | Назначение |
|---|---|
| [plan.md](plan.md) | Гипотеза, метрики, MDE, критерии успеха, рубрика — зафиксированы до прогона |
| [prompts.py](prompts.py) | Тексты промптов A/B и общие параметры генерации |
| [dataset.csv](dataset.csv) / `dataset.xlsx` | 30 запросов в 11 категориях с эталонными ключевыми пунктами |
| [run_ab.py](run_ab.py) | Прогон датасета через A и B, замер латентности, сборка файла для слепой оценки |
| `blind_eval.xlsx` | Слепая оценка: ответы X/Y в случайном порядке + заполненные оценки |
| `_key/answer_key.csv` | Ключ X/Y → A/B (закрыт на время оценки) |
| [analyze.py](analyze.py) | Раскрытие ключа, метрики, перестановочный тест, bootstrap-ДИ, проверка критериев |
| [report.md](report.md) | Автоматический отчёт по метрикам и категориям |
| `results_raw.csv`, `results_unblinded.xlsx` | Сырые ответы и раскрытые оценки |
| [homework_answer.md](homework_answer.md) | Итоговый ответ на домашнее задание с выводами |

## Как повторить

```bash
pip install -r requirements.txt
export OPENAI_API_KEY=sk-...   # или положить в .env
python run_ab.py               # ~60 запросов к gpt-4o-mini, центы
# заполнить жёлтые колонки в blind_eval.xlsx, не открывая _key/
python analyze.py              # report.md
```

Повторный `run_ab.py` перезапишет ответы и оценки — для нового эксперимента лучше копировать проект.
